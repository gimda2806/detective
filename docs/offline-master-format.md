# 오프라인 전용 마스터 포맷

`data/pending-cases/<ID>/Case-No-<NNN>.offline.json` 이 갖춰야 하는 것.

**이 문서가 기준이다**(2026-09-21 사용자 결정). 지금까지 이 규칙은 세 군데에
흩어져 있었다 — `case_master.schema.json` 의 설명문, `validate_master.ts` 의
검사 함수들, 그리고 CLAUDE.md 의 절 몇 개. 그래서 **스키마가 「오프라인에서는
필수」라고 적어 둔 규칙이 아무 데서도 안 돌고 있는** 일이 실제로 일어났다
(`check:case` 는 JSON 스키마를 돌리지 않는다). 앞으로는 여기를 고치고, 검사기를
여기에 맞추고, **벗어난 판본을 고친다** — 이 순서다.

## 왜 원본과 다른 파일인가

같은 번호를 두 경로가 다른 데이터로 연다. `/offline` 만 이 파일을 보고, AI
경로와 목록 화면은 원본 `<ID>.master.json` 을 그대로 본다(원본은 지우지 않는다).

가르는 이유는 하나다 — **오프라인 GM 에게는 모델이 없다.** AI 경로는 빈칸을
즉흥으로 메우지만 이쪽은 못 메운다. 그래서 **마스터에 안 적힌 것은 오프라인에
없는 것**이고, 원본에서 선택이던 필드들이 여기서는 필수가 된다.

## 필수 — 없으면 `check:case` 가 선다

`validate_master.ts` 의 `checkOfflineSkeleton` 이 **파일 이름이 `.offline.json` 으로
끝나거나, 원본이 `case_registry.json` 에 없을 때(= 새 사건)** 붙어서 본다(2026-09-27
사용자 결정 「입구 막기」 — 그 전에는 판본에만 돌았다). 전부 `severity: 'error'` 다.
**등록된 옛 원본에는 안 돈다** — 그 부채는 `npm run audit:offline` 이 번호순으로 세고
판본 루틴이 메운다. CI 는 PR 에서 새로 추가된 마스터를 `check:case <ID> --new` 로 돌려
registry 등록이 같은 PR 에 들어 있어도 새 사건으로 본다.

| 필드 | 없으면 무엇이 안 되나 |
| --- | --- |
| `characters[].points_finger` | 관계 질문 뒤에 그 사람이 아무도 가리키지 않는다 — 다섯이 저마다 다른 곳을 가리켜야 생기는 어긋남에서 이 사람만 빠진다 |
| `characters[].comic_tell` | 인물의 버릇을 런타임이 못 꺼낸다(`npc-voice.ts`·`offline-engine.ts`) |
| `characters[].knowledge_limits` | 그 사람이 **모르는 것**의 경계가 없어진다(`master-index.ts`) |
| `evidence[].points_at` | `SUSPICION_THIN`·`TESTIMONY_*` 세 검사가 **통째로 안 켜진다**. 어느 쪽으로도 안 기우는 카드는 **`null` 로 적는다** — 키가 없는 것과 다르다 |
| `evidence[].mismatch` | 물증이 「무엇이 있었다」로 끝나고 「있어야 할 자리에 없다」가 사라진다 |
| `red_herrings[].character_id` | 런타임이 `surface_suspicion` **문장에서 이름을 찾는** 폴백으로 떨어진다 → 가나다순으로 먼저인 사람이 주인이 된다 |
| `red_herrings[].weight` | 헛다리가 「그럴 만한 사람」에서 그치고 「그날 그럴 수 있었던 사람」이 안 된다. **하위 칸 넷(`motive` M## · `opportunity` · `means` · `means_first_reading`)을 다 채운다** — 빈 문자열은 `OFFLINE_WEIGHT_EMPTY`가 막는다(2026-09-27 사용자 결정 「채운다」. 판본 넷의 6곳이 비어 있었다) |
| `red_herrings[].clearing_points_at` | 헛다리를 지우는 것이 진범 쪽으로 한 걸음이 되지 않는다 |
| `relationships[].id` | 관계를 가리킬 이름이 없다 |
| `locations[].access_level` | 지도가 통제 구역을 구분해 그릴 수 없다(`access` 는 서술문이라 UI 가 못 읽는다) |
| `locations[].connects_to` | 지도에 연결선이 안 그려진다 |
| `motives`/`times`/`methods` | **가설 보드가 안 켜진다.** 네 칸이 다 굳어야 증거 제시와 대립 단계가 같이 열리므로, 없으면 2막 자체가 없다 |
| 후보의 `suggested_by`·`cue` | **후보를 떠올리게 하는 재료**(들은 말 F-/S- 가 기본, 카드 E 도 됨)와 그 본문에 든 핵심어. 재료가 수첩에 닿기 전에는 그 후보를 적을 수도 들이댈 수도 없다 — 없으면 옛 판본처럼 늘 열려 있고, 그러면 카드 0장으로 전원 소거가 된다. 파일에 하나라도 있으면 후보 전원이 가져야 하고, 재료 중 하나는 1막에서 들을 수 있어야 한다(`BOARD_SUGGESTER_MISSING`·`BOARD_SUGGESTER_UNKNOWN`·`BOARD_CUE_MISSING`·`BOARD_SUGGESTER_ACT2_ONLY`, `checkHypothesisBoard`) |

같이 붙는 것 둘:

- **`HERRING_OWNER_MISMATCH`** — `character_id` 가 **엉뚱한 사람**일 때 운다.
  `surface_suspicion` 에 그 사람 이름이 없고 남의 이름만 있으면 어긋난 것이다.
  **전수 플레이는 이것을 못 잡는다** — 모든 카드를 모두에게 내밀기 때문에
  조건만 차면 주인이 누구든 헛다리가 풀린다.
- **`REFERENCE_OWNERSHIP`** — id 가 **그 자리에 올 수 있는 것인가**. 원본에도
  돈다. `points_finger.at`(존재·자기 자신 아님)·`because`/`opens`(그 **인물
  자신의** knows/initial_claims)·`clearing_points_at`(존재·주인공 아님)·
  `weight.motive`(M## — 빈 문자열은 `OFFLINE_WEIGHT_EMPTY`가 따로 막는다)·`weight.means`(존재하는 카드이고 그
  카드의 `points_at` 이 이 인물).

## 사건마다 달라서 강제하지 않는 것

없어도 되는 게 아니라 **있고 없고가 사건에 달린** 것들이다.

- `relationships[].says.<CH>` — 그 관계에 낀 사람만 말한다. 피해자(V##)는
  면담할 수 없으므로 빠진다.
- `suspect_refutations.<CH>` — **진범을 뺀 전원**이 가지는 편이 맞다(2026-09-24
  CASE012 에서 확인). 헛다리 주인은 필요 없다고 적혀 있었는데, 엔진이 「누가」
  지목으로 헛다리를 터뜨리는 것을 **`how_to_clear` 의 카드가 다 제시됐을 때만**으로
  좁힌 뒤로(CASE030 에서 카드 0장으로 헛다리가 공짜로 풀리던 것을 막은 것),
  1막에서는 카드를 못 내미니 남의 카드가 낀 헛다리는 1막에서 절대 안 터진다.
  그때 `suspect_refutations` 가 없으면 「아닙니다」 한 줄만 돌아온다. 헛다리는
  2막에서 카드로 푼다.
- `full_truth.accomplice` — 공범이 있는 사건만.
- `full_truth.cover_up_method`/`cover_up_target` — 은폐가 있는 사건만.
- `locations[].detail_rules[].requires` — 선행 조건이 있는 규칙만.

## 대사 — 무엇이 말이고 무엇이 지문인가

오프라인 GM 은 마스터의 문장을 **그대로** 화면에 내보낸다. 모델이 없으니
「이건 이 사람이 하는 말이다」를 눈치로 붙여 줄 수 없고, 값의 **모양**으로만
가른다. 그런데 열한 판본이 같은 필드를 저마다 다른 모양으로 적고 있었다
(2026-09-23 실측) — `relationships[].says` 는 51 줄이 맨문장이고 28 줄이
따옴표에 싸여 있었고, `pressure_responses` 는 CASE001 만 「몰리면 절차
설명으로 돌아간다」는 **행동 서술**이고 나머지 열 판본은 **그 사람의 대사**
155 줄이었으며, CASE007 의 증언 카드 열 장은 「위슬아는 …라고 인정한다」는
3인칭 보고문이었다. 엔진이 끝맺음을 보고 대사인지 지문인지 짐작해 덮고
있어서(`asQuote`·`asSpeech`·`pressureLine`) 화면에서는 티가 덜 났지만, 그건
**런타임이 데이터의 흔들림을 덮어 준 것**이지 포맷이 정해진 것이 아니다.
그래서 여기 적는다. 원칙은 하나다:

> **필드 자체가 말이면 맨문장으로 적고, 필드가 말과 지문을 다 담을 수
> 있으면 따옴표가 둘을 가른다.** 따옴표는 런타임이 세운다.

### 말 필드 — 그 사람이 하는 말 한 줄. **맨문장**

| 필드 | 누가 | 런타임이 세우는 자리 |
| --- | --- | --- |
| `characters[].initial_claims[].content` | 그 인물 | 첫 면담·알리바이·증언 카드 턴 (`asQuote`) |
| `characters[].pressure_responses[]` | 그 인물 | 카드가 안 먹힌 턴, 몇 번째 밀렸는지 순서대로 (`pressureLine`) |
| `characters[].points_finger.says` | 그 인물 | 「○○과 어떤 사이였는지 묻는다」의 답 뒤, 상대가 `at`일 때 (`asQuote`) |
| `relationships[].says.<CH>` | 그 인물 | 「○○과 어떤 사이였는지 묻는다」 첫 박자 (`asQuote`) |
| `motives/times/methods[].refutation` | `refuted_by` 인물 | 보드의 틀린 칸을 그 사람에게 들이댔을 때 |
| `suspect_refutations.<CH>.text` | 그 인물 | 「누가」 칸을 헛다리 없는 사람에게 들이댔을 때 |
| `evidence[].reaction.jiwoo` / `.detective` | 한지우 / 탐정 | 물증 카드를 손에 넣은 턴 (`asQuote`) |

- **겉따옴표를 감싸지 않는다.** 런타임이 씌우므로 감싸면 두 겹이 되거나
  (`pressureLine` 은 벗겨서 다시 씌운다) 판본마다 모양이 갈린다.
- **속에 큰따옴표를 쓰지 않는다.** 남의 말을 옮길 때는 작은따옴표나
  「…라고」로 푼다 — 런타임이 겉에 큰따옴표를 씌우면 속의 것과 겹친다.
- **3인칭 지문으로 쓰지 않는다.** 「…을 반복하며 서류 이야기로 돌아간다」는
  작성자가 언제 쓰라고 적은 메모이지 그 사람이 하는 말이 아니다.
  `pressure_responses` 가 오래 그 모양이었는데, 런타임은 그 줄을 「곽태섭은
  …돌아간다」로 읽어 주는 수밖에 없어 **다른 네 사람은 말하고 이 사람만
  해설되는** 화면이 됐다. 말투는 존댓말이고, 「…됩디까?」「…얘기라.」처럼
  꼬리 절로 끝나는 입말은 그대로 둔다 — 끝맺음을 강제하지 않는다.
- `voice_profile.verbal_tic` 은 여기 들지 않는다. 지문이되 문구만
  작은따옴표로 적는 자리다(「'규정상'을 방패처럼 앞에 세운다」).

### 지문 필드 — 3인칭 서술. 따옴표 없음, 말 끝맺음 없음

| 필드 | 무엇 |
| --- | --- |
| `characters[].knows[].content` | 그 인물이 가진 사실. 「21시경 밸브를 잠갔다.」 |
| `characters[].comic_tell` · `knowledge_limits[]` | 버릇 · 모르는 것의 경계 |
| `characters[].points_finger.reveals` | 이 지목이 실제로 알려 주는 것. **작성용** — 런타임은 읽지 않는다 |
| `relationships[].private_strain` | 감추고 있는 쪽이 주어인 서술(`strainSubject`) |
| `contradiction_stages[].release.scope` · `player_action` | 무엇을 인정하는가 · 탐정이 무엇을 들이대는가 |
| `red_herrings[].actual_reason` | 「실제로는 …」. 헛다리가 풀릴 때 서술로 나간다 — 따옴표를 씌우면 본인이 자기를 3인칭으로 부른다 |

이 필드가 `…습니다`·`…어요` 로 끝나면 런타임이 대사로 오인해 없던 화자를
세운다. 반대로 `knows[].content` 는 「들은 진술」 보드에 **그대로** 뜨므로
「~는 사실을 안다」로 감싸지도 않는다(스키마 설명 그대로).

### 기록 필드 — 둘 다 담긴다. **따옴표가 가른다**

`evidence[].content` 하나다. 카드는 수첩에 꽂히는 **기록**이라 물증이면
지문이고 증언이면 말인데, 같은 필드라 모양으로 갈라야 한다.

- **물증 카드** — 3인칭 지문. 「구급함 안쪽 고정 밴드 두 칸 중 한 칸이 비어
  있고, 그 자리만 먼지가 앉지 않았다.」
- **증언 카드**(`discovery_condition` 이 「○○에게」로 **시작** — 엔진이 그
  사람의 카드로 보는 규칙 그대로다) — **그 사람의
  말을 큰따옴표로 감싼 것.** 「"어머, 어르신은 벌써 채밀대에 나와
  계셨어요. …"」. 「위슬아는 …라고 인정한다」는 보고문으로 쓰지 않는다 —
  「○○에게 묻는다」를 눌렀는데 돌아오는 것이 그 사람의 말이 아니라
  해설이면, 다른 인물의 카드와 서식이 갈린다.

여기서만 따옴표를 **쓴다**. 말 필드에서 따옴표를 빼는 것과 같은 이유다 —
누가 세우든 한 군데서만 세운다.

### 검사

`checkOfflineSpeech`(`validate_master.ts`)가 **오프라인 판본에만** 붙어
`severity: 'error'` 로 잡는다(2026-09-23, 새 검사는 warn 으로 두지 않는다는
결정 그대로).

| 코드 | 무엇 |
| --- | --- |
| `OFFLINE_SPEECH_SHAPE` | 말 필드가 따옴표에 싸였거나 속에 큰따옴표가 있거나 `…다.` 로 끝나는 3인칭 지문이다 / 지문 필드가 따옴표에 싸였거나 `…요`·`…니다` 로 끝난다 |
| `OFFLINE_TESTIMONY_UNQUOTED` | 증언 카드 본문이 큰따옴표로 감싸여 있지 않다 |

지문 판정은 엔진의 `pressureLine` 과 같은 규칙이다 — `다.` 로 끝나되 `니다.`
가 아니면 지문, 큰따옴표가 속에 있으면 지문에 대사가 물린 것(「…아니다.」만
예외로 지문이다 — 「니다」로 끝나지만 말이 아니다). 말 끝맺음을 강제하지
않는 것도 같은 이유다(「…뭐.」「…안 하시고.」는 대사다).


**`knows[].content` 는 지문이지만 「말하는 행위」로 끝내지 않는다**(2026-09-27 사용자 결정). 그 인물이 **아는 사실**을 적는 자리이고 플레이어 수첩에 그대로 실린다 — 「…뿐이라고 둘러댄다」라고 적으면 엔진이 3인칭 사실을 「…다고 한다」로 옮기면서 **「둘러댄다고 한다」**가 된다. 사실로 적는다(「…뿐이라고 했다」). 말하는 행위를 적어 두는 자리는 **같은 단계의 `release.scope`** 다. `OFFLINE_SPEECH_SHAPE` 가 미등록 원본과 판본에서 막고, 등록된 옛 원본의 271곳은 `npm run audit:knows-act` 가 센다.

## 단계 — 질문은 거짓 진술, 답은 카드

플레이어에게 대립 단계는 「수첩의 어느 진술을 어느 카드로 깨는가」다.
그러니 단계의 비교 진술(`requires_comparison.claim_id`)은 **그 사람이 한
거짓 진술(S-, `truth_status: lie`)**이어야 하고, 요구 카드는 그 진술을
실제로 깨야 한다.

**어긋나던 모양**(2026-09-23 사용자 지적, 11 판본 34 단계 실측). 첫 단계는
전부 거짓 진술을 질문으로 쓰는데, 둘째부터는 **앞 단계가 내준 사실(F-)**을
비교 진술로 걸어 둔 것이 14 단계였다. 이미 인정한 사실은 깰 것이 없고,
카드가 실제로 깨는 것은 앞 단계 `release.scope` 의 「다만 …라고 주장한다」
— 지문에만 있고 수첩에 진술로 남지 않는 **변명**이었다. 코퍼스 원본으로
세면 둘째 이후 단계 601 개 중 348 개(58%)가 이 모양이다.

**규칙.**

- 단계가 내주는 것은 둘이다 — **인정한 사실(F-)** 과 **변명(S-, lie)**.
  `release.claim_or_fact_id` 는 사실을, `release.scope` 는 그 인정만 적는다
  (「…한 것은 인정한다.」로 끝낸다 — 「다만 …」 은 여기 안 쓴다).
- 변명은 그 인물의 `initial_claims` 에 거짓 진술로 적고, `hidden_until` 로
  **그 사실을 전제**로 잠근다: `release_prerequisite: F-…`(그 단계가 내주는
  사실), `release_trigger`: 그 단계가 깬 진술. 엔진(`excuseClaimsFor`)이
  단계 돌파 턴에 인정 지문 뒤에 그 변명을 그 사람 입으로 내주고 수첩에
  꽂는다.
- 다음 단계는 그 변명을 `requires_heard_claim_ids` 와 `requires_comparison`
  에 건다. 카드가 깨는 것이 그 변명이어야 한다.
- 내준 사실(F-)의 본문은 **그 단계가 인정한 만큼만** 적는다. 「소란 중
  기관실로 돌아가 래치를 원위치로 걸어 두었다」를 「상태 확인하러 갔을 뿐」
  이라는 지문과 함께 내주면 사실이 지문보다 더 자백한다(CASE007 이 그랬다).
  더 깊은 진실은 그것을 인정하는 단계의 사실에 적는다.
- 단계마다 서로 다른 초기 거짓말을 질문으로 세우는 것도 된다(CASE003 의
  「암실 안 갔다 → 하역구 갈 일 없다 → 고모 재산 상관없다」). 그때도 앞
  단계의 변명이 있으면 진술로 승격해 같이 요구한다 — 카드가 둘을 다
  깨는 자리에서는 변명을 비교 진술로 건다.

**원본도 옮겼다**(2026-09-23). 348단계 중 344개를 한 번에 — `release.scope`
의 「다만 …라고 주장한다」를 1인칭 대사로 기계 변환(「…뿐이라고」→「…뿐이에요」,
「자신」→「저」, 「그녀」→「그분」)하고 걸리는 것만 손으로 썼다. 변명이 지문에
없는 「…을 인정한다」만의 단계에는 「거기까지예요. 그 이상은 아무것도 없었어요」
같은 회피 진술을 달았다. **남은 29건도 같은 날 비웠다** — 그중 23건은 아래
두 번째 모양이었고, 참 진술을 걸던 셋(058·063·064)과 남의 사실을 걸던
CASE059, 앞 단계와 어긋나던 CASE177 C04, setting 오류로 막혀 있던 CASE025 는
사건을 읽고 손으로 썼다.

**두 번째 모양 — 단계가 진술을 직접 내준다.** `release.claim_or_fact_id` 가
사실(F-)이 아니라 **진술(S-)**인 사건이 23건 있다(CASE040·041·068~075·
178~185·201~208·241). 생성 루틴이 「단계가 깨지면 새 진술 S-CH02-03 이 나온다」
고 설계해 두고 그 진술 본문을 `initial_claims` 에 안 쓴 자국이라, 다음 단계가
비어 있는 id 를 비교 진술로 걸고 있었다(검사기는 release 가 내주는 id 를
「이후 정의되는 것」으로 쳐서 안 잡았다). 이 모양은 그대로 둔다 — 그 id 로
진술을 쓰면 된다. 본문은 **인정과 변명을 한 호흡에** 담고(「제가 새벽에
건조실 근처까지 갔었어요. 하지만 안에 들어가진 않았어요.」) `truth_status: lie`,
`release.scope` 는 그대로 3인칭 지문으로 둔다. 엔진은 단계 돌파 턴에 지문을
읽고 그 id 를 `stated_claim_ids` 에 넣으므로 수첩에는 1인칭 진술이 꽂히고
다음 단계의 heard·comparison 이 그것으로 맞는다. `hidden_until` 은 그 단계의
조건(앞 단계가 깬 진술 + 그 카드)으로 걸어 두되, 오프라인은 release id 를
게이트로 안 내주므로(`unlockedByGate`) 이 게이트는 AI 경로용이다.

**검사.** `checkStageQuestion`(`STAGE_COMPARISON_NOT_LIE`, **원본·판본 모두
error**, 2026-09-23 — 남은 29건을 비운 날 올렸다) — 비교 진술이 비었거나,
F- 이거나, 없거나, 남의 것이거나,
lie 가 아니거나, `requires_heard_claim_ids` 에 없으면 선다. 마지막 조건은
원본에 올리며 처음 걸렸다 — 60건 95단계가 비교 진술을 듣기 목록에 안 넣고
있었고(엔진은 `requires_heard_claim_ids` 만 보므로 **안 들은 거짓말을 깨는**
단계가 열릴 수 있었다), 전부 그 진술을 목록에 더했다. 그러자 CASE115 가
완주에서 막혔다 — C02 가 **자기가 내주는 진술(S-CH02-02)을 자기 질문으로**
걸고 있어서, 듣기를 요구하자 영영 못 듣는 자리가 됐다(release 는 게이트로
안 흘린다). 앞 단계가 내준 변명(S-CH02-05)을 질문으로 바꿔 풀었다. **단계가
내주는 진술은 그 단계의 질문이 아니라 다음 단계의 질문이다.** 카드가 그
진술을 **실제로** 깨는지는 기계가 못 잡는다 — 판본을 쓸 때 단계마다
「이 카드들이 이 문장을 깨는가」를 한 번 읽는다.

**요구 카드는 비교 카드와 같다**(`STAGE_REQUIRES_BEYOND_COMPARISON`, **원본·판본
모두 error**, 2026-09-25). `requires_presented_evidence_ids` 에
`requires_comparison.evidence_ids` 에 없는 카드가 끼면 선다. 답은 카드이고 그
카드는 그 거짓말과 부딪치는 카드다 — 비교에 없는 카드를 요구에 끼우면
플레이어는 거짓말과 부딪치는 카드를 다 내밀고도 「한 장이 빠졌어요」에서
막히고, 그 한 장은 남의 얘기라 짐작할 길이 없다. CASE008 C01 이 그랬다 —
서준혁 헛다리(R01)를 푸는 호텔 체크인 기록(E07)이 강태민의 알리바이 단계에
끼어 있었다(실플레이 신고). 올리며 원본 108건 200단계·판본 2건이 걸려 전부
비교 카드로 잘랐다(뺀 카드의 `presentation_effect` 에서도 그 단계를 뺐다). 요구와 비교가
아예 어긋난 4단계(CASE061 C02·174 C03·212 C03·316 C03)는 비교 카드 쪽으로 맞췄다 — 잘라만
두면 요구가 비어 영영 안 열린다(CASE061 이 완주에서 걸렸다).
그 카드가 다른 자리 것이면 헛다리 `cleared_by` 나 다음 단계로 옮긴다.

**단계의 열쇠가 되는 진술은 1막에서 들을 수 있어야 한다**(`STAGE_KEY_SEALED_BY_OWN_STAGE`,
**등록 무관 error**, 2026-09-27). 단계가 「들었을 것」으로 거는 진술
(`requires_heard_claim_ids`·`requires_comparison.claim_id`)을 **그 단계나 그 뒤 단계**로
`hidden_until` 잠그면 사슬이 자기를 문다 — 말을 들으려면 단계를 깨야 하고 단계를 깨려면
그 말을 들어야 한다. 앞 단계가 내준 진술을 다음 단계가 질문으로 받는 모양(`hidden_until` 이
**앞** 단계를 가리키는 것)은 정상이라 안 선다. 올리며 원본 3건 5자리가 걸렸다
(CASE273·274·276 — 전부 진범의 `S-CH0#-01`·`S-CH0#-02` 가 자기를 깨는 단계로 잠겨 있었다).
**지금 그 다섯이 안 갇혀 있던 것은 우연이다** — 엔진은 첫 면담에서 잠긴 진술을 그냥 말해 주는데
(`offline-engine.ts` 의 `servedLater`, CASE274·276 이 남긴 자국) 첫 면담이 내주는 것은 앞
두 줄(`FIRST_MEETING_CLAIMS`)뿐이라, 그 진술이 세 번째로 밀리는 순간 단계가 영영 안 열린다.
고치는 법은 그 `hidden_until` 항목을 지우는 것이다 — 그 진술은 `initial_interview_range` 가
이미 내준다.

## 보드 재료 — 1막의 화폐는 말

가설 보드의 후보는 **떠올리게 하는 재료**(`suggested_by`)가 수첩에 닿아야
적을 수 있고 들이댈 수 있다(2026-09-25 사용자 결정). 재료는 들은 말(F-/S-)이
기본이고 카드(E)도 된다. 1막은 「누가 무슨 말을 했나」로 가설을 세워 사람에게
부딪쳐 보는 막이고, 2막은 「무엇이 남아 있나」로 거짓말을 깨는 막이다 — 화폐가
갈리므로 가설 제시와 카드 제시가 겹쳐 읽히지 않는다. 카드가 1막에 들어오는
자리는 보드의 「굳힌다」(`evidence_for`)뿐이고 거기도 손짓 없이 손에 든 것을
본다.

- **정답·오답 모두 적는다.** 오답의 재료가 곧 소거의 길이다 — 「서준혁이
  서명 얘기를 했는데」를 듣고 나서야 「재산분할 서명 때문에」를 서준혁에게
  들이댈 수 있고, 그가 「서명을 못 받았으면 살아 계셔야 받죠」로 접는다.
- **`cue` 는 재료 본문에 그대로 들어 있는 낱말 한 토막이다**(「재산분할」·
  「21시 25분」·「개인 다호」). 「그 말을 들으면 이 후보가 떠오르는가」는 사람만
  판단하지만 「그 낱말이 거기 적혀 있는가」는 기계가 본다. 시간 후보면 그
  시각, 방법 후보면 그 도구나 자리, 동기 후보면 그 이해관계의 이름.
- **허브 재료는 된다.** 한 말이 한 칸의 여러 후보를 열어도 된다 — 「협죽도
  잎이 있었다」가 방법 셋을 열고, 사람에게 들이대며 갈래를 지운다.
- 「누가」는 재료가 없다. 사람은 늘 지목할 수 있다.

판본 전부 이어져 있다(2026-09-25에 열둘을 이었고 그 뒤 판본은 처음부터 재료를 달고 태어난다). 재료가 없는 판본은 게이트 없이 종전대로
돈다. **재료 중 하나는 1막에서 들을 수 있어야 한다** — 단계가 내주는 진술과 카드를
제시해야 열리는 진술은 2막 것이다(`BOARD_SUGGESTER_ACT2_ONLY`).

## 어떻게 검사되는가

```
npm run check:case <CASE_ID>
```

오프라인 판본이 있으면 **원본과 그 파일을 따로 한 번씩** 돌린다. 출력에
`──── validate_master (Case-No-004.offline.json) ────` 섹션이 그것이다.

```
npm run check:offline
```

전 사건을 무식한 플레이어로 완주시킨다. **오프라인 판본이 있는 번호는 그
파일로 센다.** 여기서 막히는 사건은 영영 못 깨는 사건이 되고, 번호가 곧 막이라
(`case-gate.ts`) 그 막에 플레이어가 갇힌다.

```
npm run ids <CASE_ID>            인물·카드·헛다리 대응표
npm run ids <CASE_ID> <이름>      그 사람의 id 하나
npm run ids <CASE_ID> fix        character_id 를 문장 속 이름에서 채우거나 고친다
```

**마스터를 손으로 고칠 때 번호를 타이핑하지 않는다.** 이름에서 번호로 옮겨
적는 그 한 단계가 실수가 나는 자리다.

## 새 판본을 만들 때

**어느 번호를 만들지는 `npm run audit:offline`이 정한다** — 번호순으로 다음 막에 비는 번호.
차례와 회차 규칙은 `docs/offline-version-routine.md`.

원본을 복사해서 시작해도 된다 — 2막 세 건(CASE006·008·009)이 그렇게 만들어졌다.
다만 복사만으로는 위의 **필수** 표가 비므로 `check:case` 가 선다. 채워야 할
것은 사건을 읽어야 나오는 값들이고, 그중 둘만 요령이 있다.

- `points_finger` 는 **다섯이 저마다 다른 곳을 가리켜야** 한다. 진범을
  가리키는 것은 하나면 족하다 — 물어보는 족족 같은 이름이 돌아오면 세 번째쯤에
  답이 보인다. `says` 는 **「○○과 어떤 사이였는지 묻는다」의 답 뒤에 붙어
  나오므로**(2026-09-24) 질문의 답이 아니라 사이 얘기 끝에 새는 험담 모양으로
  쓴다 — 「…프런트에 계신 분이면 누가 드나들었는지 아시지 않나요」. `at` 이
  관계 격자에 없는 사람이면 그 지목은 나올 자리가 없다.
- `weight.means` 는 **그 사람 쪽으로 기울어지는 카드**(`points_at` 이 그
  인물인 것) 둘이어야 한다. 하나면 우연으로 읽히고 둘이 겹쳐야 사람이 된다.
- **소설이 먼저 있는 번호는 소설 끝의 「오프라인으로 옮길 것」이 설계도다**
  (CASE012 가 첫 예). 「새 카드로」는 `detail_rules` 한 칸과 카드 한 장, 「기존
  값에 한 줄」은 그 필드, 「`requires` 한 칸」은 그 칸이다. 옮기고 나서 소설이
  「옮기지 않는 것」으로 남긴 자리는 그대로 비워 둔다.
- `detail_rules[].requires` 에 **대립 단계(`C##`)를 걸지 않는다.** 엔진은
  받아 주지만 완주 검사기(`check:offline`)가 2막에서는 방을 다시 뒤지지 않아
  그 카드를 영영 못 줍는다. 손에 든 카드(`E##`)나 들은 말(`F-`/`S-`)로 건다.
- **판본을 만든 PR 이 판본 노트를 같이 쓴다** — `data/pending-cases/<ID>/Case-No-<NNN>.offline.md`,
  판본 파일 옆(2026-09-26 사용자 결정 — 소설 루틴의 일이 아니고, 소설에 덧붙이지 않는다.
  원본과 무엇이 달라졌는지는 판본을 만든 손이 가장 잘 안다). 모양은 `Case-No-013.offline.md`:
  소설 「오프라인으로 옮길 것」의 줄마다 무엇이 됐나, 소설이 요구하지 않았는데 온 것,
  보완점, 남은 것. 소설 끝에는 그 파일을 가리키는 「판본 노트」 한 줄만 붙인다. **판본 수는
  어느 문서에도 적지 않는다** — `ls data/pending-cases/*/Case-No-*.offline.json` 이 센다
  (2026-09-26 사용자 결정).

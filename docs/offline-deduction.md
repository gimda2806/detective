# 오프라인이 추리가 안 되는 이유 — 진단과 구조 제안

> "카드를 모으는 것도 너무 쉽고, 그럼 진상을 추측하기도 너무 쉽고, 플레이어는 일직선으로
> 범인을 알고 나서 **카드를 어떤 타이밍에 어떤 조합으로 제시해야 쟤가 자백하지?** 를
> 생각하게 된다. 누가 범인인지는 이미 알고 있으니까."
> — 2026-09-17 사용자, CASE030 실플레이 뒤

이 문서는 그 말이 맞는지를 코퍼스 309건으로 확인한 결과와, 무엇을 바꿔야 하는지의 제안이다.
**제안이지 결정이 아니다.** 뼈대를 바꾸는 항목이 섞여 있어 착수 전에 사용자 판단이 필요하다.

## 0. 우리 검사기가 이미 증명하고 있었다

`npm run check:offline`은 **아무 생각 없는 플레이어**를 만든다 — 방에 다 들어가고, 뒤질 것을
전부 뒤지고, 모두에게 모든 카드를 제시하고, 움직임이 멈출 때까지 반복한다. 추리는 한 줄도
하지 않는다.

그 플레이어가 **312건을 전부 완주한다.**

완주 가능성을 지키려고 만든 검사기인데, 같은 결과가 **바닥이 얼마나 얕은지**를 같이 재고
있었다. 이 문서는 그 바닥을 올리는 이야기다.

## 1. 사슬 네 마디

### ① 수집이 쉽다 — 어디를 볼지 고를 일이 없다

| | 사건당 평균 |
|---|---|
| 증거 카드 | 8.2장 |
| 그중 **방에서 버튼만 누르면 나오는 것**(조건 없음) | **3.9장** |
| `requires`가 걸린 것 | 2.29장 |
| 사람에게 물어야 하는 것(testimony) | 2.4장 |

`detail_rules` 1,898개 중 `requires`가 있는 것은 **707개(37%)**뿐이다. 나머지는 방에 들어간
순간부터 열려 있다.

더 근본적인 것은 **메뉴가 곧 정답지**라는 점이다. 오프라인에서 `detail_rules[].action`은
화면에 뜨는 버튼 문구 그대로다 — 「현상대 모서리를 자세히 살펴본다」가 목록에 있다. 플레이어는
*어디를 볼지 생각해 내는* 것이 아니라 *적혀 있는 것을 누른다.* 헛다리(`probe`)를 섞어 두었지만
전부 눌러 보는 비용이 0이라 걸러지지 않는다.

### ② 카드가 범인을 부른다 — 제시 전에 이미 안다

| 증거 카드가 이름을 부르는 횟수 | 진범 | 비진범 1인 |
|---|---|---|
| **제목**에 | 0.24장 | 0.59장 |
| **본문**에 | **2.21장** | **0.58장** |

제목은 오히려 진범 이름이 덜 나온다(목격자·물건 이름이 제목이니까). 그런데 **열어서 읽으면
본문이 진범을 3.8배 부른다.**

- **진범이 단독 최다로 불리는 사건: 162 / 309 (52%)**
- 레드헤링 주인공이 본문에 불리는 횟수: 평균 0.70장

절반의 사건에서 **수첩에서 이름을 세기만 하면 범인이 나온다.** CASE030이 그랬다:

> **E04** 인화실 재고 장부 — "**하도영**이 주장한 심야 재고 정리 작업 기록이 남아 있지 않다."

카드 본문이 **「그의 알리바이는 거짓이다」라는 결론을 미리 적어 두었다.** 제시해서 알아낼 것을
주우면서 알게 된다.

### ③ 움직이는 사람이 하나뿐이다

| | |
|---|---|
| 대립 단계를 **진범만** 가진 사건 | **305 / 309건 (98.7%)** |
| 진범 사슬 길이 | 3단계 236건 · 4단계 72건 |
| 끝내려면 **진범 한 명에게** 들이대야 하는 카드 | 평균 **6.5장** |
| → 전체 카드(8.2장)의 | **79%가 진범 전용** |

`present` 말고는 무엇도 상태를 바꾸지 않는데, 그 `present`를 받아 주는 사람이 한 명이다.
그래서 처음 말이 바뀌는 순간 게임이 스스로 범인을 알려 준다 — ②에서 이미 알고 있지 않았더라도.

### ④ 남은 것은 조합 맞추기다

확정이 끝난 뒤에도 카드 6.5장이 남아 있고, 그것을 **정해진 순서의 3~4단계**에 나눠 넣어야
한다. 각 단계가 앞 단계의 산출물을 요구하므로 순서는 하나로 고정돼 있다.

그래서 플레이어의 머릿속이 「누가 왜」가 아니라 **「어떤 조합으로 넣어야 열리지」**가 된다.
사용자의 말 그대로다.

여기에 더해 `contradiction_stages[].player_action`이 **1,006개 전부 채워져 있는데 엔진이 한
번도 읽지 않는다.** 그 필드에 「무엇이 어긋나는지」가 적혀 있다:

> **C02**: 환풍기 스위치의 조작 흔적(E02)과 채이든의 증언(E07)을 근거로, 평소엔 늘 켜져 있던
> 환풍기가 그날 밤에만 꺼져 있었다는 사실을 추궁한다.

화면에 나간 것은 공용 한 줄이었다: "아까 하신 말씀과는 맞지 않는데요." **단계와 단계를 잇는
논리가 마스터에 있는데 화면이 말하지 않는다.**

# 목표 — 플레이어가 추리소설 한 편을 써내려가는 느낌

> "플레이어가 직접 추리소설 한 편을 써내려가는 느낌을 주는 게 offline의 목표야.
> 마스터는 그거에 맞게 다시 쓰면 되는 거니까, 로직이 돌아갈 구조를 짜 주기만 하면 돼."
> — 2026-09-17 사용자

**아래는 그 목표에 맞춘 구조 설계다. 마스터 포맷은 이 구조에서 끌어냈다** — 지금 309건을
지키려고 타협하지 않았다.

지금 플레이어는 **읽는 사람**이다. 마스터가 쓴 문장이 버튼 순서대로 공개되고, 마지막에
전말이 통째로 나온다. 써내려가게 하려면 플레이어가 **문장을 만들어 내는 자리**가 있어야 한다.

## 1. 구조 — 가설 보드

추리소설의 뼈대는 **누가 · 언제 · 왜 · 어떻게** 넷이다. 마스터의 `full_truth`가 정확히 그
모양이다(`responsible_character_id` / `key_time_location` / `motive` / `method`). 그것을 정답으로만
쓰지 말고 **플레이어가 채우는 빈칸 넷**으로 연다.

```
┌─ 수사 가설 ─────────────────────────────┐
│  누가   [ 하도영 ]      근거  E04        │
│  언제   [ 22시 전후 ]   근거  E07        │
│  왜     [ ? ]           근거  —          │
│  어떻게 [ 실족으로 위장 ] 근거  E01 E03  │
└─────────────────────────────────────────┘
```

「언제」를 넣는 이유(2026-09-17 사용자 결정): 시각이 곧 단서인 사건이 많고, CLAUDE.md가
시각을 아라비아 숫자로 쓰라고 못 박은 것도 플레이어가 두 시각을 맞춰 보게 하려는 것이다.
그런데 지금은 맞춰 본 결과를 **적을 자리가 없다.** 「언제」 칸의 틀린 후보를 반박하는 재료는
`actual_timeline[].world_fact`다 — "그 시각엔 아직 살아 있었다"는 목격이 곧 반박이다.

- 각 칸은 **후보 중에서 고르고**, 그 선택의 **근거 카드를 함께 건다**.
- 채운 칸은 **인물에게 들이댈 수 있다.** 그것이 지금의 「증거 제시」를 대체한다.
- 보드가 곧 플레이어가 쓰고 있는 원고다. 고쳐 쓸 수 있고, 비워 둘 수 있다.

### 1.1 틀린 가설이 전진이다

이 구조의 핵심이다. 지금은 틀린 제시가 **아무 일도 아니다**("그래서요?"). 바꾸면 틀린 가설은
**반박당하고, 그 반박이 새 사실을 준다.**

> 「왜: 후원금 갈등」을 예소담에게 → "그 계약은 제가 아쉬울 게 없어요. 다음 시즌 후원은
> 이미 서면으로 끝났습니다." → **그 사실이 수첩에 들어온다.**

그래서 플레이어는 틀려도 판을 좁힌다. 전원을 찍어 보는 것이 최적 전략이 되지 않는 이유도
여기다 — 찍으려면 근거 카드를 걸어야 하고, 근거 없이는 칸을 못 채운다.

**여기가 `knowledge_limits`가 살아나는 자리다.** 1,536/1,538명(99.9%)에 채워져 있는데 엔진이
한 번도 안 읽는 그 필드가 곧 「그 사람이 그럴 수 없었던 이유」다.

### 1.2 대결과 해결편

네 칸이 다 맞으면 **대결**이 열린다. 지금의 `contradiction_stages`가 그대로 여기서 굴러간다 —
다만 **이미 확정한 뒤**라 조합 맞추기가 아니라 몰아붙이기로 읽힌다.

해결편은 **플레이어가 채운 것으로 조립한다.** 마스터의 완성된 산문을 쏟지 않는다:

> "하도영 씨. 장부는 초저녁에 멈춰 있었고(**E04**), 환풍기는 그날 밤에만 꺼져 있었습니다
> (**E02·E07**). 그리고 현상대 모서리만 닦여 있었죠(**E01**)."

플레이어가 안 쓴 근거가 있으면 한지우가 그 자리에서 짚는다 — "이건 안 쓰셨네요." 그것이
**내가 쓴 원고**라는 감각을 만든다.

## 2. 로직 명세

### 2.1 상태

```ts
hypothesis: {
  who:  { id: CharacterId, basis: EvidenceId[] } | null
  when: { id: TimeId,      basis: EvidenceId[] } | null
  why:  { id: MotiveId,    basis: EvidenceId[] } | null
  how:  { id: MethodId,    basis: EvidenceId[] } | null
}
refuted: { who: CharacterId[], when: TimeId[], why: MotiveId[], how: MethodId[] }
act: 1 | 2            // 2막 = 네 칸 정답
```

### 2.2 판정 — 칸마다 따로, 조합으로 보지 않는다

조합(5인물 × 4시각 × 4동기 × 4수법 = 320가지)에 전부 반박을 쓰는 것은 불가능하다. **칸 단위로
본다.** 그러면 마스터가 써야 할 반박은 **5 + 4 + 4 + 4 = 17개**로 떨어지고, 그중 「누가」의 반박은
레드헤링이 이미 절반을 들고 있다(아래 3.1).

| 판정 | 조건 | 결과 |
|---|---|---|
| 칸을 못 채움 | 근거 카드가 0장 | 채우기 자체가 안 된다 |
| 후보가 틀림 | 그 칸의 정답이 아님 | **반박** — 그 후보가 `refuted`로 가고, 반박 문장이 사실로 수첩에 들어온다 |
| 후보는 맞고 근거가 약함 | 정답이지만 근거가 `evidence_for`에 없음 | 「심증은 알겠는데 그걸로는 안 됩니다」 — **몇 장** 모자란지만 말한다(무엇인지는 말하지 않는다, 지금 `openStageShortfall`과 같은 규칙) |
| 맞음 | 정답 + 근거 충족 | 그 칸이 **확정**된다 |
| 네 칸 확정 | | **2막 개시** |

### 2.3 턴 흐름

```
1막  장소를 돈다 / 사람을 만난다 / 카드를 줍는다
     └→ 가설 보드의 칸을 채운다 (카드를 걸고 후보를 고른다)
        └→ 인물에게 들이댄다
           ├ 틀림 → 반박 + 새 사실 → 후보가 줄어든다
           └ 맞음 → 칸 확정
     (네 칸 확정)
2막  대결 — contradiction_stages 가 순서대로 굴러간다
     └→ 자백
종결  해결편을 플레이어가 건 근거로 조립해 읽는다
```

### 2.4 지금 코드에서 바뀌는 곳

| | 지금 | 바뀜 |
|---|---|---|
| 「사건 종결」 버튼 | 조건 없이 전말 공개 | **가설 보드 열기**. 종결은 자백 뒤에만 |
| `present\|<카드>\|<인물>` | 바로 `contradiction_stages` 판정 | 1막에선 가설 칸에 거는 행위, 2막에선 지금 그대로 |
| `firingStage` | 언제나 열림 | `act === 2`에서만 |
| 헛제시 응답 | 공용 시치미 | 칸 반박(`refutation`) |
| 엔딩 | `ending_scene.narrative` 통째 | 플레이어가 건 근거로 조립 |

## 3. 마스터 포맷

이 구조가 요구하는 것만 적는다. **기존 필드로 되는 것은 새로 만들지 않는다.**

### 3.1 새로 필요한 것

```jsonc
"motives": [                       // 칸 '왜'의 후보. 4개 안팎
  { "id": "M1", "text": "위작이 발각될 위기",       "truth": true,
    "evidence_for": ["E05", "E06"] },
  { "id": "M2", "text": "다음 시즌 후원금 갈등",     "truth": false,
    "evidence_for": ["E08"],
    "refutation": "그 계약은 이미 서면으로 끝났습니다. 제가 아쉬울 게 없어요.",
    "refutation_releases": "F-CH03-04" }   // 반박이 주는 새 사실(선택)
],
"methods": [ /* 칸 '어떻게'. 같은 모양 */ ],
"times":   [ /* 칸 '언제'. 같은 모양. 반박 재료는 actual_timeline[].world_fact */ ],
"suspect_refutations": {           // 칸 '누가'. 레드헤링이 없는 인물만 필요하다
  "CH02": { "text": "그 시간엔 2층에 올라갈 수 없습니다.",
            "releases": "F-CH02-02" }
}
```

- `refutation`은 **그 후보가 아닌 이유**다. 틀린 가설을 전진으로 만드는 물건이라 **가짜 후보에
  반드시 있어야 한다.** 정답 후보(`truth: true`)는 `refutation`이 없고 `evidence_for`가 지목의
  근거다.
- `refutation_releases`는 그 반박이 수첩에 남기는 사실. 없으면 말만 하고 끝난다.

**레드헤링은 그대로 둔다**(2026-09-17 사용자 결정 — 두는 쪽이 더 재밌다). 흡수하지 않고
**맞물리게** 한다:

> 「누가」 칸에 어떤 인물을 걸었을 때, 그 사람의 레드헤링이 **아직 안 풀렸으면** 그 지목이
> 레드헤링을 푼다 — 몰린 사람이 `actual_reason`을 털어놓는 것이 곧 반박이다. **이미 풀렸으면**
> "그 얘기라면 아까 말씀드렸잖아요"로 받고 `suspect_refutations`로 떨어진다.

그래서 레드헤링이 있는 인물(사건당 2명)은 `suspect_refutations`가 **필요 없다.** 나머지 셋만
쓰면 된다. 두 장치가 서로를 대신하지 않고 서로를 부른다 — 레드헤링은 1막의 결이고,
지목은 그것을 터뜨리는 방아쇠다.

### 3.2 규칙만 바뀌는 것 (필드는 그대로)

- **`evidence[].content`는 사실만 적는다.** 「**하도영**이 주장한 기록이 없다」가 아니라
  「장부가 초저녁에 멈춰 있다」. 지금 본문이 진범 이름을 3.8배 부르는 것(진단 ②)이 가설
  보드를 무의미하게 만든다 — 칸을 채우기 전에 답이 보이면 쓸 것이 없다.
- **`knowledge_limits`가 `suspect_refutations`의 재료다.** 99.9% 채워져 있다.
- **`reason_for_limit_or_lie`가 가짜 동기의 재료다.** 거짓 진술의 100%(1,149개)에 「왜
  숨기는가」가 적혀 있고, 그 대부분이 살인이 아닌 다른 비밀이다.

### 3.3 그대로 쓰는 것

`contradiction_stages`(2막), `player_action`(추궁 문장), `pressure_responses`, `locations`,
`characters`, `relationships`, `actual_timeline`.

## 4. 단계적 도입

**한 사건으로 끝까지 해 보고 판단한다.** 309건을 손대기 전에 구조가 실제로 재미있는지부터 본다.

1. **런타임 골격** — 가설 보드, 칸 판정, 2막 게이트. 마스터가 새 필드를 안 가진 사건은
   **지금처럼 동작한다**(가설 보드 없이 1막을 건너뛴다). 그래야 309건이 안 깨진다.
2. ~~**`player_action` 살리기**~~ — ✅ 2026-09-17 구현됨. 단계가 터지는 턴에 공용 다그침 대신 마스터의 추궁이 나간다.
3. **시범 사건 하나**를 새 포맷으로 다시 쓴다(CASE030이 적당하다 — 실플레이 로그가 있다).
   다만 CASE030은 **「언제」 칸의 재료가 지금 없다**: `actual_timeline`이 전부 "사건 당일 늦은
   밤"이고 `world_fact`가 흔적("환풍기가 멈추고 암실 안이 조용해진다")이 아니라 행동 묘사
   ("하도영이 당황하며 말을 얼버무린다")다. 다시 쓸 때 시각을 숫자로 박고 `world_fact`를
   **세상에 남은 흔적**으로 고쳐야 「언제」의 반박이 생긴다 — 로그 리뷰 4번과 같은 작업이다.
4. 플레이해 보고 **2번 문단(틀린 가설이 전진이다)이 실제로 그런지** 확인한다.
5. 되면 생성 지침을 바꾸고, 기존 사건은 이주 루틴이 배치로.

### 무엇으로 확인하나

`check:offline`의 무식한 플레이어에 값을 하나 더 붙인다 — **네 칸이 확정되기까지 밟은 턴 수**.
지금 구조에서는 0에 수렴한다(수첩만 보면 아니까). 이 값이 올라가지 않으면 포맷을 바꾼 보람이
없는 것이다.

완주 검사는 그대로 돌린다. **버튼만으로는 못 끝내는 사건**을 만드는 것이 여전히 가장 큰
위험이고, 새 포맷이 없는 309건이 1번 항목대로 계속 완주되는지가 그 안전선이다.

## 5. 정한 것과 기본값

**정한 것**(2026-09-17 사용자):

- 칸은 **넷** — 누가·언제·왜·어떻게.
- 레드헤링은 **둔다.** 흡수하지 않고 「누가」 지목과 맞물린다(3.1).

**기본값**(구조를 돌리기 위해 이렇게 두고, 시범 사건을 플레이해 본 뒤 고친다):

| | 기본값 | 이유 |
|---|---|---|
| 틀린 가설의 대가 | **없음.** 기록에만 남는다 | 반박이 사실을 주므로 그 자체가 결과다. 근거 없이는 칸을 못 채워 무한 찍기도 안 된다 |
| 근거 카드 수 | 칸마다 **최소 1장**. 정답 칸은 건 카드 중 **하나라도** `evidence_for`에 있으면 확정 | 전부 요구하면 다시 조합 맞추기가 된다 |

## 6. 엔진과 화면의 경계

가설 보드는 화면이 크다. 오프라인 UI는 다른 세션이 맡고 있으므로(`docs/handoff.md`) 이 브랜치는
**엔진 계약**까지만 한다 — 행동 id, 응답 모양, 상태. 화면은 그 계약 위에 그쪽이 그린다.

```
행동   hypothesis|set|<칸>|<후보id>|<카드id,...>     칸을 채운다
       hypothesis|clear|<칸>                          비운다
       hypothesis|press|<칸>|<인물id>                 채운 칸을 인물에게 들이댄다
응답   gm.hypothesis: { who, when, why, how, refuted, act }   매 턴 실린다
       gm.message 에 반박/확정 서술, jiwoo_line 에 몇 장 모자란지
```

새 필드(`motives`/`times`/`methods`)가 없는 사건은 **가설 보드가 열리지 않고 지금처럼 동작한다.**
그래야 309건이 안 깨지고, 시범 사건 하나로 판단할 수 있다.

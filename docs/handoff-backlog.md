# 밀린 목록 — 쪽지에서 접어 올린 것 (살아 있는 파일)

`docs/handoff/`의 쪽지는 **받는 쪽이 지운다**(규칙 #3). 그런데 받는 쪽이 루틴이면 회차마다 세션이
새로 떠서 아무도 지우지 않고, 세션마다 그 쪽지를 전부 다시 읽고, 다른 세션이 같은 항목을 다시
재고 다시 쪽지로 쓴다 — 2026-09-21에 51장, 2026-09-26에 다시 58장이 그렇게 쌓였다(같은 요청이
셋씩 겹쳤다: 진범의 `knows`가 빈 것 3장 · 말버릇 축 3장 · `requires`에 사람 이름 2장). 그래서
**루틴 앞으로 온 쪽지의 열린 항목은 여기로 접고 원본은 지운다.** 원문은 git 이력에 있다(줄 끝의 접미 id).

**이 목록은 「누가」가 아니라 「무엇」으로 묶인다.** 세션 이름은 사라지지만 일감은 남는다.

## 이 파일을 어떻게 쓰나

- **세션은 시작할 때 자기 절만 읽는다** — 생성 루틴은 「생성 루틴」, 이주 루틴은 「이주 루틴」. 남의 절과
  남의 쪽지는 읽지 않는다(제목만 훑는다). 전부 읽는 것이 빙빙 도는 원인이었다.
- **집었으면 그 줄 끝에 `— 진행 중 (브랜치)`를 적고 push한다.** 두 세션이 같은 날 같은 실측을 두 번 한
  사고가 있었다(2026-09-26 은폐 축). **끝냈으면 줄을 지운다** — 체크만 하고 두면 일지가 된다.
- **사용자 판단이 필요한 것은 처음부터 「사용자」 절에 적는다.** 쪽지에 적으면 아무도 못 집고 사흘씩 읽힌다.
- **알림(「해야 할 것: 없다」)은 쪽지도 여기도 아니다** — 그 루틴의 회차 기록(소설은 `docs/novels/rounds.md`)에.
- 마스터 한 건의 어긋남은 **그 번호를 여는 회차가** 같이 고친다(한 사건은 한 회차만 만진다). 그래서 번호별로 적는다.

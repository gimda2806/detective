> 자리당 6~8쌍이면 충분하지만 헛짚음처럼 자주 나오는 자리는 더 있어도 좋다.

# 탐정·한지우 주고받기 — 쓸 자리 목록

오프라인 GM(`app/gm/offline-engine.ts`)에서 두 사람이 **서로에게** 말하는
자리는 증거를 찾은 순간(`BANTER_DISCOVERY`, 131쌍 + `EXCHANGE_DISCOVERY`
16벌)이다. `HINT_BANTER`(6상황 × 4쌍)는 **지금 호출되는 곳이 없다** —
「막혔어요」는 대사가 아니라 진짜 다음 스텝이어야 한다는 2026-09 사용자
결정으로 `requestHint()`가 다시 `nextHint()`의 한 줄 안내를 그대로 쓰게
됐다(AI 화면과 같아졌다). 풀 자체는 지우지 않고 남겨 뒀다. 나머지 27개
풀은 전부 한쪽만 말하고 끝난다. 가장 아픈 자리가 단계 돌파다:
`DETECTIVE_BREAK`와 `JIWOO_BREAK`가 같은 턴에 같이 나오는데 **따로 뽑히므로
서로 답을 하지 않는다.**

이 문서는 그 자리들을 채우기 위한 것이다. 쌍을 여기 쓰면
`offline-engine.ts`의 풀로 옮겨 붙인다.

---

## 공통 규칙 (전부 코드에 이미 적혀 있는 것)

1. **말투 비대칭.** 탐정은 한지우에게 반말, 한지우는 탐정에게 반존대(`-요`).
   이건 명시적으로 유지 결정된 것이라 바꾸지 않는다.
2. **한지우는 판단하지 않는다.** 방금 벌어진 것을 되짚거나 핀잔을 줄 뿐,
   **다음에 누구를 볼지 고르지 않고** 무엇이 해결됐다고 선언하지 않는다.
3. **한 번뿐인 과거 사건을 넣지 않는다.** "어제 우산은 못 찾으셨으면서"가
   311건에 돌아가면 탐정은 매 사건마다 어제 우산을 잃어버린 사람이 된다.
   관계의 이력(`탐정님 펜은 늘 제가 찾아드리는데`)이나 한지우 자신의
   배경(`제가 회사 다닐 때`)은 매번 참이라 괜찮다.
4. **사건 내용을 넣지 않는다.** 인물 이름·장소 이름·카드 제목·시각이
   들어가면 그 사건에서만 맞는 대사가 된다. 311건 전부에서 참이어야 한다.
5. **`lead`가 누가 먼저 여는지를 정한다.** 한 자리 안에서 두 방향이 섞여야
   관계가 한 방향으로 굳지 않는다 — 탐정이 지시하고 한지우가 되받는 박자와,
   한지우가 찌르고 탐정이 받아치는 박자 둘 다 필요하다. 대략 반반.
6. **자리당 6~8쌍.** 주고받기는 한마디보다 훨씬 빨리 닳는다. 두 줄짜리
   대화는 두 번째 보면 바로 "아까 그거"가 된다.

형식:

```ts
{ lead: 'jiwoo',     jiwoo: '"…"', detective: '"…"' },
{ lead: 'detective', jiwoo: '"…"', detective: '"…"' },
```

`lead: 'jiwoo'`면 한지우 줄이 먼저 찍히고 탐정이 받는다. 반대도 같다.

# 지금 쓸 자리 넷

## A. 단계 돌파 — `BANTER_STAGE_BREAK` (8쌍)

**가장 먼저.** 이 게임의 클라이맥스인데 지금 두 사람이 각자 허공에 말한다.

- **언제**: 증거를 들이대서 상대의 말이 바뀐 순간. 카드 여러 장을 늘어놓은
  턴이면 늘어놓기 → 다그침 → 상대의 새 진술 뒤에 붙는다.
- **지금**: `DETECTIVE_BREAK` 3줄 + `JIWOO_BREAK` 6줄이 따로 뽑힘.
- **쓸 수 있는 것**: 방금 말이 바뀌었다는 사실, 탐정이 맞았다는 것,
  아직 끝이 아니라는 것, 받아 적는 일.
- **쓰면 안 되는 것**: 누가 범인인지 암시, 다음에 무엇을 할지, 인물 이름.
  ("이제 저 사람이 범인이네요" 같은 줄은 규칙 2번 위반이면서 스포일러다.)

예시 두 쌍(톤 기준으로만 — 바꾸셔도 됩니다):

```ts
{ lead: 'detective',
  jiwoo: '"…지금 말씀이 아까랑 다르네요. 둘 다 적겠습니다."',
  detective: '"둘 다 적어. 어느 쪽이 참인지는 나중에."' },
{ lead: 'jiwoo',
  jiwoo: '"방금 숨 한 번 쉬신 데, 거기도 적을까요?"',
  detective: '"적어. 말보다 그게 정확할 때가 있어."' },
```

빈 슬롯 6쌍:

```ts
{ lead: '', jiwoo: '""', detective: '""' },
{ lead: '', jiwoo: '""', detective: '""' },
{ lead: '', jiwoo: '""', detective: '""' },
{ lead: '', jiwoo: '""', detective: '""' },
{ lead: '', jiwoo: '""', detective: '""' },
{ lead: '', jiwoo: '""', detective: '""' },
```

## B. 헛다리 해소 — `BANTER_HERRING_CLEAR` (6쌍)

- **언제**: 한 사람의 의심이 벗겨진 순간(`cleared`). 마스터의 해명
  (`actual_reason`)이 나온 직후.
- **지금**: `JIWOO_HERRING_CLEAR` 6줄만. 탐정은 자기가 틀렸던 것에 대해
  **아무 말도 안 한다.**
- **쓸 수 있는 것**: 한 명 줄었다는 것, 의심했던 데 대한 겸연쩍음,
  줄어든 게 반가운 건지 모르겠다는 감각, 지운 이유도 기록이라는 것.
- **쓰면 안 되는 것**: 남은 사람이 누구인지, 이제 누구를 봐야 하는지.

예시 한 쌍:

```ts
{ lead: 'jiwoo',
  jiwoo: '"…이 분은 아니었네요. 사과는 제가 대신 못 해 드립니다."',
  detective: '"사과할 일은 아니야. 물어봐야 아는 거니까."' },
```

빈 슬롯 5쌍.

---

## C. 헛짚음 · 빈손 — `BANTER_DEAD_END` (8쌍)

헤매는 구간이야말로 둘이 붙어 있는 게 보여야 하는 자리다. 빈도가 제일
높으므로 여기만 8쌍.

- **언제**: 제시가 안 먹혔거나(`NPC_DEFLECT`), 뒤졌는데 아무것도 없을 때
  (`NOTHING_FOUND`).
- **지금**: `INSIGHT_WRONG_DOOR`·`INSIGHT_NOTHING_THERE`·`JIWOO_DEFLECT`·
  `JIWOO_NOTHING`이 전부 따로.
- **쓸 수 있는 것**: 없다는 것도 정보라는 것, 서로 핀잔, 다시 해보자,
  탐정의 헛다리를 한지우가 놀리는 것.
- **쓰면 안 되는 것**: **어디를 가라거나 무엇을 보라는 지시.** 그건
  힌트 버튼 몫이고, 여기서 하면 규칙 2번 위반이다.

예시 한 쌍:

```ts
{ lead: 'jiwoo',
  jiwoo: '"안 통했네요. 표정은 그대로 유지하세요."',
  detective: '"유지하고 있어."' },
```

빈 슬롯 7쌍.

---

## D. 사건을 닫고 나서 — `BANTER_AFTER_CLOSE` (6쌍)

지금 주고받기가 **아예 없는** 자리다.

- **언제**: 사건 종결. 마스터의 `ending_scene` 서술이 끝난 뒤 맨 마지막.
- **주의**: 마스터의 엔딩이 이미 두 사람의 대사로 끝나는 사건이 많다
  (CASE014는 계단 삐걱거리는 소리로 끝난다). **그 위에 얹는 것이므로
  사건을 요약하거나 마무리 짓는 말이면 안 된다** — 이미 끝난 이야기를
  한 번 더 끝내는 꼴이 된다. 사건이 아니라 **일이 끝난 것**에 대해 말한다.
- **쓸 수 있는 것**: 피곤함, 수첩 정리, 밥·퇴근, 다음 일, 아무 말 없이
  같이 걷는 것.
- **쓰면 안 되는 것**: 사건 요약, 범인 언급, 교훈.

예시 한 쌍:

```ts
{ lead: 'jiwoo',
  jiwoo: '"오늘 건 정리하는 데 좀 걸리겠는데요."',
  detective: '"천천히 해. 어차피 나도 오늘은 여기까지야."' },
```

빈 슬롯 5쌍.

# 목록 화면의 한지우 쪽지 — 더 쓸 자리

사건 목록 헤더에 붙어 있는 메모지다(`app/CaseLibrary.tsx` 의
`jiwooLinesFor`). 눌러서 다음 줄로 넘긴다. 주고받기와 달리 **한지우 혼자**
말하고, 사건 이야기가 아니라 **탐정의 일 진행 상태**에 대해 말한다.

## 단이 여섯이고, 단마다 따로 써야 한다

해결 비율(`푼 사건 / 수사 가능 사건`)로 갈린다. 지금 수사 가능한 사건이
54건이라 실제 구간은 이렇다. **비율이라 사건이 늘면 구간도 같이 늘어난다.**

| 단 | 조건 | 지금 기준 | 지금 | 목표 |
|---|---|---|---|---|
| 첫 사건 | 푼 게 0 | 0건 | 3줄 | 6~8 |
| 초반 | 10% 미만 | 1~5건 | 3줄 | **8~10** |
| 중반 | 35% 미만 | 6~18건 | 3줄 | **8~10** |
| 후반 | 75% 미만 | 19~40건 | 3줄 | 6~8 |
| 막바지 | 75% 이상 | 41~53건 | 3줄 | 6 |
| 전부 종결 | 전부 | 54건 | 3줄 | 5~6 |

**초반·중반이 제일 급하다.** 대부분의 플레이 시간이 거기 있고, 목록은 사건을
고를 때마다 보는 화면이라 세 줄은 금방 다 읽힌다.

## 쓸 수 있는 숫자 넷

문장에 숫자를 넣을 때는 **반드시 이 자리표를 쓴다.** "세 건이요"처럼 박아
두면 그 단에 들어온 한순간 말고는 전부 틀린 말이 된다.

| 자리표 | 뜻 |
|---|---|
| `${solved}` | 종결한 사건 수 |
| `${unopened}` | 아직 안 연 사건 수 |
| `${total}` | 수사 가능한 사건 수 |
| `${inProgress}` | **열어만 두고 안 끝낸 사건 수** (이번에 새로 열었다) |

`${inProgress}` 는 목록이 이미 세고 있는데 이 쪽지가 한 번도 쓴 적 없던
숫자다. 한지우가 가장 자연스럽게 핀잔 줄 수 있는 자리라 열어 뒀다 —
**0이면 그 줄은 아예 안 나온다**(0건이라고 말하면 거짓말이 되므로, 단 뒤에
조건부로 붙는다). 그래서 이 숫자를 쓰는 줄은 단과 무관하게 따로 모아
주셔도 된다.

## 규칙

위의 공통 규칙 여섯 개가 그대로 적용된다. 이 자리에서 특히 조심할 것 넷:

1. **첫 줄은 언제나 0번이 나온다.** 서버가 그린 것과 브라우저가 처음 그린
   것이 같아야 해서(안 그러면 하이드레이션이 깨진다) 난수도 시각도 못 쓴다.
   그러니 **각 단의 첫 줄을 가장 무난한 것으로** 두시면 좋다 — 그게 제일
   많이 읽힌다.
2. **"전부"라고 말하는 줄은 전부 종결 단에만.** 예전에 해결 건수(10건)로
   갈랐다가, 19건 푼 사람에게 "전부 종결. 서류함이 비었어요"를 말한 적이
   있다. 6% 푼 사람에게 할 소리가 아니었다.
3. **사건 이야기는 안 한다.** 이 화면은 어떤 사건에도 속하지 않는다.
   인물 이름도 사건 제목도 나올 수 없다.
4. **탐정에게 반존대(-요)**. 여기도 같다.

## 형식

단만 표시해서 주시면 됩니다. 자리표는 `${...}` 그대로 쓰시면 됩니다.

```
[초반]
"${solved}건 끝났네요. 서류함은 아직 그대로고요."
"..."
"..."

[중반]
"..."

[열어만 두고 안 닫은 게 있을 때]
"열어만 두고 안 닫은 게 ${inProgress}건 있는데요."
"..."
```

## 지금 있는 것 (톤 기준)

- 첫 사건 — `"커피는 제가 내렸어요. 사건은 직접 고르세요."`
- 초반 — `"밤새워 보실 거예요? ...뭐, 말려도 안 들으시겠지만."`
- 중반 — `"해결한 건만 다시 읽으시는 거, 저 봤어요."`
- 후반 — `"이쯤이면 제가 배울 차례인 것 같은데요."`
- 막바지 — `"마지막 몇 건은 천천히 하세요. 끝나면 심심해지거든요."`
- 전부 종결 — `"서류함이 비었어요. 이런 날은 좀 쉬셔도 돼요."`

주고받기보다 한 뼘 더 사적이어도 되는 자리다. 사건 중에는 둘 다 일하는
중이지만, 목록은 일과 일 사이라 한지우가 탐정을 사람으로 보는 말이 나올 수
있다(커피, 밤샘, 서장님 얘기가 지금 그래서 들어가 있다).

# 긴 주고받기 (`EXCHANGE_*`) — 더 쓸 자리

두 줄짜리와 **같은 네 자리**에 쓰는, 여섯~아홉 줄짜리다. 지금 열 개 있다:

| 자리 | 지금 | 한 사건에서 몇 번 나오나 | 더 쓰면 좋은 개수 |
|---|---|---|---|
| `EXCHANGE_STAGE_BREAK` | 3개 (평균 7줄) | 대립 단계 수만큼 (보통 2~3번) | **8~10** |
| `EXCHANGE_AFTER_CLOSE` | 3개 (평균 9줄) | 1번 | **6~8** |
| `EXCHANGE_HERRING_CLEAR` | 2개 (평균 8줄) | 헛다리 수만큼 (보통 2번) | 5~6 |
| `EXCHANGE_DEAD_END` | 2개 (평균 7줄) | **사건당 1번** (나머지는 두 줄짜리) | 4~6 |

## 개수가 어디에 쓰이는지

**한 사건 안에서는 같은 것이 두 번 안 나온다** — 한 번 쓴 것은 그 사건
동안 빠진다. 그래서 개수가 늘면 좋아지는 것은 **사건이 바뀔 때**다.

지금 단계 돌파가 3개인데 한 사건에서 2~3번 터지므로, **한 사건이면 거의
다 쓴다.** 두 번째 사건에서 첫 사건과 똑같은 대화가 다시 나온다는 뜻이다.
여기가 제일 급하다.

종결 후는 사건당 한 번뿐이라 3개면 세 사건까지는 안 겹치지만, **사건에서
마지막으로 읽는 대사**라 반복이 제일 크게 걸린다. 두 번째로 급하다.

헛짚음은 사건당 한 번으로 막아 뒀으니 2개로도 두 사건은 간다.

## 형식

```ts
[
  j('"지우 대사."'),
  d('"탐정 대사."'),
  j('"지우 대사."'),
  d('"탐정 대사."'),
],
```

`j()`는 한지우, `d()`는 탐정이다. **번갈아 나오지 않아도 된다** — 한쪽이
연달아 두 줄을 말해도 되고(한 줄로 받고 한 줄 더 얹는 박자), 마지막을
누가 잡느냐가 그 대화의 맛이다.

그냥 이렇게 주셔도 옮겨 붙이겠습니다:

```
지우: "..."
탐정: "..."
지우: "..."
```

## 두 줄짜리와 다르게 쓸 것

- **두 줄은 반응이고, 긴 것은 장면이다.** 두 줄짜리가 "방금 그거 봤어요?"
  라면, 긴 것은 거기서 한 번 더 파고들어 서로에 대한 말이 나오는 자리다.
  지우가 찌르고 → 탐정이 피하고 → 지우가 다시 파고들고 → 탐정이 결국
  한 마디를 내주는 박자가 지금 열 개에 공통으로 들어 있다.
- **마지막 줄이 제일 중요하다.** 긴 대화는 끝에서 기억된다. 「"그래도 안
  떠나잖아." / "...그건 맞습니다."」처럼 한쪽이 지는 듯이 인정하는
  자리거나, 「"역시 이럴 줄 알았습니다."」처럼 당하는 것을 알면서 따라가는
  자리가 좋다.
- 규칙은 위의 공통 규칙 여섯 개 그대로다. 길어질수록 4번(사건 내용 금지)이
  깨지기 쉬우니 그것만 조심하면 된다.

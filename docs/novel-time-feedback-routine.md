# 소설이 메운 시각을 마스터로 되먹이는 루틴

`npm run check:novel`이 세는 **`TIME_NOT_IN_MASTER` 232개(소설 92편)**가 이 루틴의
입력이다. 소설이 쓴 시각 중 마스터에 없는 것이고, **그 소설의 「보탠 것」/「오프라인으로
옮길 것」 절에 왜 넣었는지가 이미 적혀 있는 것들**이다(적혀 있지 않은 것은
`TIME_UNRECORDED`로 따로 샌다 — 아래 2번 일감).

## 왜 따로 두나

되먹이는 **방법**은 이미 [`docs/novels/README.md`](novels/README.md)에 상세히 있다.
**여기에 그것을 다시 쓰지 않는다** — 갈라지면 서로 다른 말을 하게 된다. 없는 것은
방법이 아니라 **차례**다.

README의 되먹임 절은 **「그 번호를 나중에 다시 쓸 때」**를 전제로 쓰여 있다. 오프라인
전용 마스터를 만드는 시점에 소설을 읽고 출발하라는 것이고, 그건 옳다. 다만 **그 시점이
대부분의 번호에는 오지 않는다** — 판본이 있는 번호는 몇 개 안 된다(`npm run audit:offline`이 센다). 그래서 232개가
형식까지 맞춘 채로 아무도 안 읽는 자리에 쌓여 있다(2026-09-24 확인).

**시각만은 그 조건 없이 지금 되먹일 수 있다.** 카드·`requires`·`hidden_until`은 오프라인
판본의 설계에 얽혀 있어 다시 쓸 때 같이 정해야 하지만, `actual_timeline`의 빠진 칸은
**두 경로가 같이 읽는 원본 마스터의 결함**이고 소설이 이미 그 자리를 정확히 짚어 뒀다.

본보기가 CASE008의 21:03이다 — `T10`이 21:00에 제다실(`L03`)에서 다호에 섞었다고 적는데
**다호는 마당 건너 `L02`**다. 두 장소를 오간 3분이 마스터에 없다. 소설은 그 3분을 채우고
로비 카메라 테이프의 21:00~21:03 카드까지 제안해 뒀다. **지어낸 분위기가 아니라 마스터
결함 보고서에 수정안이 붙은 것이다.**

## 한 회차 — 5편

`npm run check:novel`을 돌려 `TIME_NOT_IN_MASTER`가 **많은 편부터** 다섯 편을 맡는다.
많은 쪽이 마스터 타임라인이 가장 성긴 사건이다. 현재 머리는
CASE263(17) · CASE265(14) · CASE045(13) · CASE269(10) · CASE180(9)이다.

**시작할 때 셋을 본다** — `docs/novels/README.md`의 「다음 차례」 한 줄이 겹침을 못 막은
전례가 있다(그 문서의 표 참고). ① `git fetch` ② `npm run check:novel`의 **실제 출력**
③ `docs/handoff/`의 남은 쪽지.

## 한 편에서 하는 일

1. **그 편의 「보탠 것」/「오프라인으로 옮길 것」에서 그 시각이 적힌 칸을 찾는다.**
   못 찾으면 그 시각은 이 루틴의 일감이 아니다(`TIME_UNRECORDED`로 갔어야 할 것이므로
   아래 2번으로 넘긴다).
2. **그 칸이 「마스터가 무엇을 빠뜨렸는가」를 말하고 있는지 읽는다.** CASE008처럼
   이동 시간·공백을 짚은 것이면 되먹일 것이다. 단순히 장면 분위기를 적은 것이면
   **되먹이지 않는다** — 그 시각은 소설에만 두고 넘어간다.
3. 되먹일 것이면 `actual_timeline`에 항목 하나를 더한다. **`world_fact`를 반드시 적는다**
   — 없으면 런타임이 그 항목을 통째로 건너뛴다(`master-index.ts`의 안전 규칙).
4. `npm run build:source <CASE_ID>` · `npm run check:case <CASE_ID>` · `npm run check:novel`.

## 하지 않는 것

- **사건의 진상을 바꾸지 않는다.** 이 루틴은 빠진 칸을 채우는 것이지 다시 쓰는 것이 아니다
  (이주 루틴과 같은 규칙이다 — CLAUDE.md).
- **소설 본문을 고치지 않는다.** 여기서 움직이는 것은 마스터뿐이다.
- **카드·`requires`·`hidden_until`은 건드리지 않는다.** 그건 그 번호를 오프라인으로 다시
  쓸 때의 일이고, README가 그 규칙을 갖고 있다.
- **`TIMELINE_AFTER_ENTRY_UNUSED`(9건)는 반대 방향이다** — 마스터에 있는데 소설이 안 쓴
  것이라 소설 쪽 일감이다. 여기서 보지 않는다.

## 두 번째 일감 — `TIME_UNRECORDED` 62개

**아무 데도 근거가 없는 시각**이다. 소설이 지어냈고 왜 넣었는지도 안 적혀 있다.
같은 회차에서 그 편에 이것이 있으면 **둘 중 하나로 정리한다**:

- 마스터가 놓친 칸을 짚은 것이면 → 「오프라인으로 옮길 것」에 한 줄 적는다.
  그러면 다음 실행에서 1번 일감으로 올라온다.
- 그냥 분위기용이면 → **소설에서 그 시각을 뺀다**(「그 무렵」 같은 말로 바꾼다).
  근거 없는 숫자는 플레이어가 나중에 마스터와 맞춰 볼 때 가짜 모순으로 읽힌다.

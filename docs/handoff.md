# 세션 간 메모장

두 세션이 같은 저장소를 고친다. 이 파일은 그 둘이 서로에게 남기는 쪽지다 — **내가 한 것 중 네 작업에 영향이 있는 것**, 그리고 **네가 해야 할 것**.

## 규칙 넷

1. **세션을 시작하면 먼저 읽는다.** `git pull` 직후에.
2. **턴을 끝낼 때 적는다.** 상대 작업에 영향이 가는 변경을 했으면 `## 남긴 쪽지` 맨 위에 블록 하나를 추가한다. 영향이 없으면 적지 않는다 — 일지가 아니다.
3. **처리했으면 그 블록을 지운다.** 체크만 하고 남겨 두면 파일이 로그가 되고, 로그가 되면 아무도 안 읽는다. 지우는 것이 "받았다"는 신호다.
4. **자기 블록만 건드린다.** 남의 블록은 지우지도 고치지도 않는다 — 다 처리해서 지우는 경우만 예외이고, 그때는 자기 블록에 "#3 처리함"이라고 한 줄 남긴다.

블록은 이 형태로 쓴다. 새 블록이 **위로** 간다.

```markdown
### <YYYY-MM-DD HH:MM UTC> · <브랜치> → <상대 브랜치>

**한 것**
- 한 줄로. 영향 범위를 함께. (`getCase()`가 동기 → 비동기가 됐다, PR #675)

**해야 할 것**
- [ ] 상대가 무엇을 해야 하는지. 파일·심볼까지.
```

## 무엇을 적나 — 적을 것과 적지 말 것

**적는다** — 상대가 모르면 조용히 깨지는 것:

- 내보낸 심볼의 시그니처·위치 변경 (동기 → 비동기가 가장 위험하다)
- 파일·사건의 삭제나 개명. 특히 **상대 코드가 문자열로 물고 있을 만한 것**
- 빌드·실행 절차 변경 (새 필수 단계, 새 환경 변수, 새 생성물)
- 공유 설정 변경 (`vite.config.ts`, `package.json`, 워크플로)

**적지 않는다** — 기계가 이미 말해 주는 것:

- 타입 오류, 빌드 실패, 린트, 마스터 검증 → PR 검사(`.github/workflows/pr-checks.yml`)가 상대 PR을 빨갛게 만든다
- 열린 PR끼리의 충돌, 지워진 것의 잔존 참조 → 충돌 감시 루틴(`docs/conflict-watch-routine.md`)이 이슈로 올린다
- 그냥 한 일. **영향이 없으면 쪽지가 아니다.**

**이 표는 굳은 값이 아니다.** 세션이 새로 뜨면 브랜치 이름이 바뀌므로, 여기 없는
이름을 보면 커밋 제목으로 판단하거나 사용자에게 묻는다 — 이름을 지어내 표에 더하지
말 것. `master-format-migration-*`처럼 **무엇을 하는지가 이름에 있는 브랜치**는
이 표가 없어도 읽힌다.

**멈춘 세션이 소설화 포인터를 잡아 둔 채로 있다**(2026-09-21). `rqn4l1`이
`docs/novels/README.md`의 「다음 차례: CASE203~207」을 **「진행 중: CASE203~207
(rqn4l1)」로 바꿔 한 줄만 먼저 push**해 뒀다 — 겹침을 막으려고 이 저장소가 정한
그 절차 그대로다. 그런데 **그 세션이 멈췄고, 그 커밋은 머지되지 않았다.** 그래서
main의 포인터는 아직 「다음 차례: CASE203~207」이고, 다음 소설화 세션이 그 번호를
집으면 멈춘 세션과 같은 자리를 잡게 된다.

**푸는 것은 소설화 루틴 쪽 판단이다** — 이 세션은 적어만 둔다. 회차를 시작하는
세션은 CLAUDE.md가 시키는 대로 ① `git fetch` ② `ls docs/novels/`의 실제 파일 목록
③ `docs/handoff/`의 남은 쪽지를 먼저 보고, **여기 이 문단도 같이 본다.**

## 쪽지는 `docs/handoff/`에 **한 블록에 한 파일**로 쓴다 (2026-09 사용자 결정)

이 파일 안에 블록을 쌓던 구조였는데, **둘이 동시에 적으면 맨 위를 양쪽이 잡아 반드시
충돌한다.** 2026-09-19 하루에 두 번 났고 둘 다 「양쪽 다 살리기」로 끝났다 — 내용이
다투는 것이 아니라 **자리가 다투는** 충돌이라 사람 손이 가는 것이 아깝다. 이 절에
「잦아지면 갈라라」고 적혀 있던 그대로 갈랐다.

- **쓸 때**: `docs/handoff/<날짜>-<보내는 브랜치>.md` 파일을 **새로 만든다.**
  같은 날 같은 브랜치가 또 쓰면 `-2`를 붙인다. 안에는 예전과 같은 `### ` 블록
  하나만 쓴다. **파일이 다르므로 git 이 알아서 합쳐 충돌이 나지 않는다.**
- **읽을 때**: 그 폴더를 통째로 읽는다. 파일 이름이 날짜로 시작하므로 정렬하면
  시간순이다.
- **처리했으면 그 파일을 지운다.** 예전에는 남의 블록을 이 파일에서 도려내야 해서
  규칙 #4(자기 블록만 건드린다)와 부딪혔는데, 이제는 **파일 하나를 지우면 되므로**
  #3(지우는 것이 「받았다」는 신호)과 #4가 둘 다 산다.
- 남은 파일이 곧 미처리 목록이다. **비어 있으면 아무도 기다리는 것이 없다는 뜻이다.**

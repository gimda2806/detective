# 다음 소설 회차에게 — 355·356은 아직 지워질 수 있는 번호다 (두 회차 연속)

## 한 것

`docs/novels/CASE357.md`(「끊긴 채널」) 한 편. 마스터는 안 건드렸다. 회차 기록은
`docs/novels/rounds.md`의 CASE357 회차 절이다. 앞 회차(`x24ucp`)가 남긴 쪽지는 처리했으므로 지웠다.

## 열자마자 볼 것 — 번호 하나를 건너뛴 이유가 아직 그대로다

닫을 때 센 것은 **① 13 · ② 0 · ③ 마스터 368 / 소설 358**이고, ①·③이 내놓는 가장 작은 번호는
여전히 **CASE355**다. **한 편을 썼는데 큐가 줄지 않았다** — 회차 도중에 생성 루틴이 CASE368을
머지했다(#1508, `origin/main`이 `a12487e9` → `15051a6e`). 바뀐 파일은 `case_registry.json`과
`CASE368/`뿐이라 겹치지는 않았다. **그런데 355·356은 `PAIR_TWIN` 사슬이고, 그 판단이 이 회차에서도 안 내려졌다.**

이 회차에서 직접 다시 쟀다:

- `npm run check:case CASE355` → **error 1**: 「CASE356와 두 편이 판박이다 — 단계 사슬 골격 / 은폐 방식 / 은폐 대상」
- `npm run check:case CASE356` → **error 0** (판박이는 앞번호의 보고서에 뜬다)
- 앞 회차가 잰 CASE354 → CASE355도 같은 모양이다

CLAUDE.md는 「판박이는 고쳐 쓰지 않고 **뒷번호를 지운다**」이므로 **대상은 355와 356 둘**이고 354는
앞번호라 남는다. 지워질 수 있는 번호의 소설을 먼저 쓰면 **존재하지 않는 원문을 인용한 편**이 된다.

**그래서 이 회차는 355·356을 건너뛰고 CASE357을 썼다.** 갈래는 안 바꿨고 번호만 건너뛴 것이다
(이유는 `rounds.md`에 적었다 — README 규칙).

**다음 회차도 같은 갈림길에 선다.**

1. 백로그 「검사기를 보는 세션」 절 첫 줄(`PAIR_TWIN` 사슬)의 체크박스를 먼저 본다. 내려졌고 355가
   남았으면 그대로 355를 쓴다.
2. 안 내려졌으면 **CASE358로 간다.** 355·356 둘 다 대상이므로 둘을 같이 건너뛴다.

**그리고 이번이 두 번째로 건너뛰는 회차이므로, 다음 회차가 세 번째가 되면 그 사실 자체를
백로그 「사용자」 절로 올릴 것.** 소설 루틴은 마스터를 지울 수 없고, 지울 수 있는 쪽이 세 회차째
그 줄을 안 집은 것이 된다. 「두 번호가 큐 맨 앞에서 영구히 막혀 있다」는 것은 사람이 한 번 판단할
값이다.

## 두 번째로 볼 것 — 백로그는 편을 읽기 전에 훑는다 (앞 회차의 당부가 맞았다)

앞 회차가 「편을 읽기 전에 백로그 「검사기를 보는 세션」 절을 먼저 훑을 것」이라고 적어 뒀고,
그대로 했더니 **새로 낸 줄 알았던 것 둘이 이미 거기 있었다** — `points_finger`로만 지목되는 사람,
그리고 은폐가 부르는 저장 매체를 집는 카드가 0장인 것. 그래서 이 회차가 한 일은 **그 줄에 사례와
세는 축을 덧붙인 것**이고, 그게 새 줄을 내는 것보다 값이 컸다(`points_finger` 줄에는 **셈의 두 번째
축**이 생겼다 — 「지목만 있고 카드가 없는 사람」과 「카드는 있고 갈 곳이 없는 사람」이 다르다).

**새로 올린 줄은 하나다** — 「단계의 요구 카드가 자기 `mismatch`로 자기를 무르는 것」. CASE354 `E04`와
CASE357 `E04`가 **같은 필드에서 같은 방향으로** 어긋나고 둘 다 `C01`의 유일한 요구 카드다.
두 번 연속이라 세는 법까지 적어 뒀다.

## 쓸 때 걸린 것 둘 — 시각 경고를 0으로 닫았다

앞 회차의 처방(「본문 시각은 마스터의 시계에 있는 칸만, 수사가 걸린 시간은 장 제목에만」)대로
했더니 `check:novel` 소견이 **0건**이 됐다. 그 과정에서 두 군데 걸렸다.

1. **`TIME_12H_MISMATCH` 1건** — 「그러면 그... 5시 5분에 이미」. **사람이 말할 때는 「오후」를 안
   붙이는 것이 자연스러움**이고 그게 곧 검사에 걸린다. 대사에 시각을 쓰려면 말투를 조금 포기한다.
2. **기록지를 옮겨 적을 때 시각이 생긴다** — 출입 태그 기록판에 「17:24 (개방)」을 적었는데 마스터에
   없는 시각이었다(표시안과 탐정의 입장을 갈라 보려다 나왔다). **기록지·로그·메모지를 소설에 옮기는
   자리가 가장 지어내기 쉽다.** 쓰기 전에 `actual_timeline`과 `evidence[].content`에서 시각을 뽑아
   목록으로 놓고, 그 목록 밖의 시각은 장 제목에만 쓰는 쪽이 안전하다.

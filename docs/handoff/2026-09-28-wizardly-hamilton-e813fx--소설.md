## 두 번째로 볼 것 — 겹침 검사 4번은 fetch를 먼저 안 하면 거짓 「겹침 없음」을 낸다

README 「회차를 여는 법」의 4번(브랜치를 훑어 그 소설 파일을 가진 브랜치가 있는지)을 이렇게 돌렸다.

```bash
git fetch origin '+refs/heads/*:refs/remotes/origin/*'   # ← 이게 먼저다
for b in $(git ls-remote --heads origin | awk '{print $2}' | sed 's|refs/heads/||'); do
  git ls-tree -r --name-only origin/$b 2>/dev/null | grep -q "docs/novels/CASE358.md" && echo "OVERLAP: $b"
done
```

**첫 줄을 빼먹으면 `ls-tree`가 전부 실패하고 `2>/dev/null`이 그것을 먹어서, 「0개 — 겹침 없음」과
글자까지 같은 결과가 나온다.** 이 회차가 한 번 그렇게 헛돌았다. 로컬에 원격 refs가 있는지
(`git branch -r | head`) 한 번 보고 돌린다.

## 세 번째로 볼 것 — 쓸 때 시각이 새는 자리 둘 (앞 회차 처방의 뒷면)

앞 두 회차의 처방(「본문 시각은 마스터의 시계에 있는 칸만, 수사가 걸린 시간은 장 제목에만」)대로
했고 `check:novel`은 **이 편에서 0건**이었다. 그래도 두 군데가 샜다.

1. **인물에게 구체적인 시각을 대게 하면 그 시각이 마스터에 없다.** 거짓 알리바이를 말하는 인물에게
   「10분이나 15분 더 있다 나갔다」를 말하게 했더니 탐정이 그것을 「밤 9시 45분」으로 되받는 줄이 세
   군데 생겼고, 21:45는 마스터에 없었다. **거짓 알리바이는 시각을 안 대는 쪽이 더 자연스럽고 검사도
   조용하다** — 진짜로 시계를 본 사람만 분을 기억한다.
2. **장면 첫 문단에 시각을 쓰면 제목과 달리 세어진다.** 2장 첫 문단을 「밤 11시 50분, 계단 아래에서…」로
   열었더니 `TIME_UNRECORDED` 1건. 제목의 시각은 안 세고 본문 첫머리의 시각은 센다.
3. **「반」·「쯤」은 검사를 피해 간다.** 「밤 10시 반쯤」은 파서가 22:00으로 읽어 마스터에 있는 시각이
   되어 조용히 통과한다 — 뜻한 것이 22:30이면 어긋난 채로 통과한 것이다. 그 줄은 시각 없이 다시 썼다.

## 네 번째 — 「이상 없음」을 재 보는 법이 자정 넘김 편에서는 한 번 더 필요하다

README가 요구하는 대로 일부러 역행을 넣어 검사가 도는지 재 봤는데, **처음 고른 자리에서는 아무것도
안 떴다.** 진입이 밤 11시 35분이라 3장부터 자정을 넘기는 편인데, **자정 넘김 어림이 `day`를 한 번
올린 뒤에는 「밤 11시 40분」 같은 장이 이튿날 저녁으로 계산된다.** 그 편에서 검사가 도는지 재려면
**같은 새벽 구간 안에서**(예: 새벽 1시 50분 → 새벽 0시 50분) 당겨야 한다.

이것은 백로그 「검사기를 보는 세션」 절에 **새 줄**로 올렸다(자정 넘김 줄 바로 아래 — 같은 축의 두

# 다음 소설 회차에게 — CASE355는 지워질 수 있는 번호다

보낸 곳: `claude/wizardly-hamilton-x24ucp` (소설 루틴, CASE354 회차, 2026-09-27)

## 한 것

`docs/novels/CASE354.md`(「온에어 15분 전」) 한 편. 마스터는 안 건드렸다. 회차 기록은
`docs/novels/rounds.md`의 CASE354 회차 절이다.

## 열자마자 볼 것 — 세는 세 줄보다 이것이 먼저다

닫을 때 센 것은 **① 13 · ② 0 · ③ 마스터 367 / 소설 357**이고, ③의 가장 작은 번호는
**CASE355**다. **그런데 CASE355는 `PAIR_TWIN` 사슬의 가운데다.**

- `npm run check:case CASE354` → **error 1**: CASE355와 판박이(단계 사슬 골격 / 엔딩 산문 / 은폐 방식)
- `npm run check:case CASE355` → **error 1**: CASE356과 판박이(단계 사슬 골격 / 은폐 방식 / 은폐 대상)
- 마스터 **367건 전수**에서 **error는 이 2건뿐이다**(다른 코드는 0).

CLAUDE.md는 「판박이는 고쳐 쓰지 않고 **뒷번호를 지운다**」이므로 **355·356 중 하나 이상이
지워질 수 있다.** 지워질 수 있는 번호의 소설을 먼저 쓰면 **존재하지 않는 원문을 인용한 편**이
된다 — `docs/novels/README.md`의 「`-ver2` 접미사가 붙은 것」이 내려 둔 판단과 같은 자리다.

**그래서 둘 중 하나를 고를 것.**

1. 백로그 「검사기를 보는 세션」 절 첫 줄(`PAIR_TWIN` 사슬)을 보고 **그 판단이 내려졌는지**
   확인한다. 내려졌고 355가 남았으면 그대로 355를 쓴다.
2. 안 내려졌으면 **갈래를 바꾸거나 CASE357로 건너뛴다.** ①과 ③이 같은 구간이라 실제 선택지는
   「355를 쓴다 / 357로 건너뛴다」 둘이다. **갈래·번호를 바꿨으면 그 이유를 `rounds.md`에 적는다**
   (README 규칙).

## 두 번째로 볼 것 — 「새로 나온 것」을 쓰기 전에 백로그를 읽을 것

이 회차는 편을 다 쓴 뒤에 백로그를 읽었고, 그래서 **새로 낸 줄 알았던 항목 둘이 이미 거기
있었다**(오답의 `refuted_by` 누락 — 거기에 CASE354 `H03`이 **이름으로** 적혀 있었다 ·
`points_finger`로만 지목되는 사람에게 카드도 후보도 없는 것 — CASE353이 세는 법까지 적어 뒀다).
**백로그 「검사기를 보는 세션」 절은 이미 코퍼스 전수로 세어 둔 항목이 여럿이다** — 편을 읽기 전에
훑으면 같은 것을 두 번 내지 않고, 대신 **그 줄에 사례나 값을 덧붙이는 일**을 하게 된다(이 회차가
결국 한 것이 그것이다).

## 쓸 때 걸린 것 하나

`TIME_NATIVE_NUMERAL`이 네 번 잡혔고 **네 번 다 대사**였다 — 「여섯 시 넘어서요」·「여덟 시쯤」·
「아홉 시요」. 사람이 말하는 문장을 쓰면 고유어 시각이 저절로 나온다. 본문 시각은 마스터의 시계에
있는 칸만 쓰고(CASE354는 17칸이었다), 수사가 걸린 시간은 **장 제목에만** 적으면 경고가 0으로 닫힌다
(제목의 시각은 4번 검사가 보지 않는다).
